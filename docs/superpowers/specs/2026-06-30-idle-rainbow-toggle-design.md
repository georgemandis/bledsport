# Idle Rainbow Animation Toggle — Design

**Date:** 2026-06-30
**Component:** `bLEDsport-game-server`

## Goal

Add a config option that turns the waiting-phase LED animation on or off.

- **Default: off.** While waiting for players, the LED strip is fully dark.
- **On:** restores the existing idle animation — gentle rainbow sweep across the
  middle LEDs plus the orange/blue portal glow at the ends.

## Background

During the `waiting` game phase, `server.js` renders an idle animation
(`server.js`, waiting-phase block around line 1013):

- A portal-glow effect at each end, gated on `gameConfig.portalsEnabled`.
- A "gentle rainbow idle" loop filling the middle LEDs
  (`PORTAL_GLOW_SIZE … NUM_LEDS - PORTAL_GLOW_SIZE`).

It then calls `sendToWled(pixels)` and `broadcast({ type: 'state', gamePhase:
'waiting', ... })`.

The config system is schema-driven: `CONFIG_SCHEMA` in `server.js` defines every
option (default, category, `live` flag, and numeric bounds for sliders). The
config web UI (`index.html`) builds its controls automatically from the schema
received over WebSocket — boolean fields render as toggle rows, and labels are
auto-generated by `formatLabel(key)`.

## Design

### 1. Schema entry (`server.js`, `CONFIG_SCHEMA`, `display` category)

Add next to `ledBrightness`:

```js
idleRainbow: { default: false, category: 'display', live: true },
```

- Boolean → renders as a toggle row in the UI automatically.
- `category: 'display'` → appears under the existing **DISPLAY** section.
- `live: true` → applies immediately, no restart.
- `default: false` → off by default.

### 2. Gate the waiting-phase animation (`server.js`)

Wrap **both** the portal-glow block and the rainbow loop so that when
`gameConfig.idleRainbow` is false, `pixels` stays all-`null` and the strip goes
fully dark. The trailing `sendToWled(pixels)` and `broadcast(...)` calls run
unchanged, so the phase still reports `waiting` and the web mirror stays in sync.

```js
if (gamePhase === 'waiting') {
  const pixels = new Array(NUM_LEDS).fill(null);
  if (gameConfig.idleRainbow) {
    // ...existing portal-glow block (still gated on portalsEnabled inside)...
    // ...existing gentle rainbow idle loop...
  }
  sendToWled(pixels);
  broadcast({ type: 'state', gamePhase: 'waiting', ... });
  return;
}
```

### 3. Config UI (`index.html`)

**No change required.** `formatLabel('idleRainbow')` → "Idle Rainbow", and the
toggle, label, and `config_update` wiring are all derived from the schema.

## Out of scope

- No changes to presets, the WebSocket protocol, or the playing/victory/
  sudden-death phases.
- The "off" state intentionally darkens the portal glow as well as the rainbow
  (fully dark), per the agreed behavior.

## Testing

1. Start the server; open the config page.
2. Confirm an **Idle Rainbow** toggle appears under **DISPLAY**, defaulting to off.
3. With it off, verify the LED strip (and the web canvas mirror) is dark during
   the waiting phase.
4. Toggle it on; confirm the rainbow sweep and portal glow return immediately
   (live), with no game restart.
5. Toggle off again; confirm it goes dark again.
